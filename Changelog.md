# Changelog

All notable changes to `problem_details` are documented here. Breaking changes are marked with ⚠️.

## [Unreleased]

- XML bodies now declare the namespace RFC 9457 Appendix B mandates (`urn:ietf:rfc:7807`).
- Arrays in XML bodies now use the representation RFC 9457 Appendix B defines — a container element holding one `<i>` element per item, e.g. `<accounts><i>/account/12345</i><i>/account/67890</i></accounts>`. Previously each item was written as a repeated sibling element (`<accounts>…</accounts><accounts>…</accounts>`), which Appendix B reads as an object with a duplicate member name rather than as an array. This changes the XML output for any extension holding a sequence.
- An extension field that is `None` is now omitted from XML bodies instead of being written as an empty element. `<absent/>` claims the value is the empty string and reads back as `Some("")`, so the same value serialized to JSON and to XML deserialized to two different things. Use `#[serde(skip_serializing_if = "Option::is_none")]` if you want the field left out of the JSON body as well. An item *inside* an array keeps its `<i/>`, since dropping it would change the length of the array.

## [0.10.0] - 2026-08-16

- The MSRV is now declared in `Cargo.toml` as `rust-version = "1.85"`.
- Updated `quick-xml` to 0.41.
- Relaxed trait bounds on the framework response impls: extensions (`Ext`) now only need `Serialize + Debug` instead of `Serialize + Clone + Send + Debug`.
- Fixed the build with just `--features poem` (the `poem` dependency now enables the `server` feature).
- `actix` module is now public, so `problem_details::actix::*` can be named directly
- `JsonError` and `XmlError` are now re-exported from the crate root and can be named directly.

## [0.9.0] - 2025-11-01 ⚠️

- ⚠️ The crate now uses **Rust edition 2024**, which raises the minimum supported Rust version accordingly (Rust 1.85+).
- **`utoipa` feature**: derives `utoipa::ToSchema` for `ProblemDetails`, so the type can be referenced in OpenAPI documents generated by `utoipa`.
- Updated `quick-xml` to 0.38.
- Updated `actix-web` to 4.11.

## [0.8.0] - 2025-02-15

- **`actix` feature**: `ProblemDetails`, `JsonProblemDetails` and `XmlProblemDetails` implement actix-web's `ResponseError`, so they can be returned from handlers directly.

## [0.7.0] - 2025-01-11 ⚠️

- ⚠️ Upgraded framework integrations to new major versions: **axum 0.8** (was 0.7) and **poem 3.1** (was 2.0). Your application must be on the same major versions.
- Updated `quick-xml` to 0.37.

## [0.6.0] - 2024-01-10 ⚠️

- ⚠️ `JsonProblemDetails` and `XmlProblemDetails` moved from the framework modules to the crate root and are now generic over the extensions type (`JsonProblemDetails<Ext>`). Import them from `problem_details::{JsonProblemDetails, XmlProblemDetails}`.
- ⚠️ Upgraded to **http 1.0** (was 0.2), **axum 0.7** (was 0.6) and **poem 2.0** (was 1.3). Your application must be on `http` 1.x.
- ⚠️ New **`json` feature**, split out of `serde` and enabled by default. With `default-features = false` you now need to enable `json` explicitly for JSON output.
- ⚠️ The `xml` feature no longer implies `poem/xml`, and `axum` / `poem` no longer imply `serde`. Enable the serialization features you need alongside the framework feature.
- `CONTENT_TYPE` constants (`application/problem+json`, `application/problem+xml`) and `to_body_string()` on both wrapper types, so bodies can be rendered without a framework.
- Explicit `JsonError` / `XmlError` error types for serialization failures.
- JSON and XML responses now set the correct `Content-Type` header consistently across axum and poem.

## [0.5.1] - 2023-10-26

- Fix for missing docs.rs content. No code changes.

## [0.5.0] - 2023-10-26

- **`poem` feature**: `ProblemDetails` implements poem's `ResponseError`, plus
  `JsonProblemDetails` / `XmlProblemDetails` response types.

## [0.4.0] - 2023-10-11

- **`axum` feature**: `ProblemDetails` implements axum's `IntoResponse`, plus
  `JsonProblemDetails` / `XmlProblemDetails` response types.
- **`xml` feature**: XML serialization via `quick-xml`.

## [0.3.0] - 2023-10-10 ⚠️

- ⚠️ Extensions are now typed: `ProblemDetails<Ext>`.

## [0.2.0] - 2023-10-09

- `ProblemDetails` implements `Display` and `std::error::Error`.

## [0.1.0] - 2023-10-08

- Initial release: the `ProblemDetails` struct with the RFC 9457 / RFC 7807 standard members (`type`, `status`, `title`, `detail`, `instance`), the `ProblemType` URI wrapper, extension support, and optional `serde` serialization (enabled by default).
